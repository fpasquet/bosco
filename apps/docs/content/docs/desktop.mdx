L'application du poste est une fenêtre Electron autour de l'interface de Bosco, avec une icône dans la barre système et des notifications natives. Elle est facultative : Bosco marche aussi dans le navigateur. Elle n'existe que pour Linux, en paquet `.deb`.

## Le paquet .deb

Le paquet embarque tout ce qu'il faut pour tourner sans le dépôt :

- **le service** de Bosco et son interface déjà construite, avec leurs seules dépendances de production ;
- **Node 26**, pour ne dépendre ni du Node du poste ni de nvm ;
- **l'application** Electron.

Il s'installe dans `/opt/Bosco`, ajoute Bosco au menu des applications et configure le bac à sable de Chromium (`chrome-sandbox`) à l'installation. Il garde les données de `~/.local/share/bosco`, les mêmes que le service lancé depuis le dépôt : passer de l'un à l'autre ne perd rien.

Chaque paquet porte la version de l'application suivie de la date et du commit, par exemple `0.1.0+git20261109073400.3118cb5`. Chaque construction est donc plus récente pour apt. Une construction depuis une copie de travail modifiée prend en plus un suffixe `.dev…`.

### Construire et installer

```bash
make desktop-package           # construit apps/desktop/out/bosco-desktop_<version>_amd64.deb
make desktop-package-install   # l'installe avec apt (sudo)
```

`make desktop-package` construit d'abord tout le dépôt (`make build`), puis prépare le paquet. Un seul `.deb` reste dans `apps/desktop/out` : les anciens sont supprimés.

`make desktop-package-install` copie le paquet dans un dossier temporaire lisible par l'utilisateur `_apt`, puis lance `sudo apt install --reinstall`. Sans ce détour, apt se plaint de ne pas pouvoir lire un fichier du dossier personnel.

### Mettre à jour

```bash
make desktop-update            # git pull, pnpm install, puis construit et installe le paquet (sudo)
```

Installé pendant que Bosco tourne, le nouveau paquet se signale : une notification « Bosco a été mis à jour » s'affiche, et le menu de la barre système commence par « Relancer Bosco · version 0.1.0 · abc1234 installée ». Bosco ne se relance jamais seul : c'est toi qui choisis le moment, entre deux tours.

Une version plus ancienne refuse de démarrer sur des données qu'une plus récente a mises à jour. Elle affiche « Tes données viennent d'un Bosco plus récent » et propose `make desktop-update`.

## Essayer une branche : make beta

Pour essayer une branche avant sa fusion, sur tes vraies données :

```bash
make beta BRANCH=feat/usage-page   # construit la branche d'origin et installe son paquet (sudo)
make beta                          # sans BRANCH : la copie de travail courante
make beta BRANCH=main              # revenir à la version stable
```

La branche se construit dans un worktree à part, `~/.cache/bosco/beta`, gardé d'un essai à l'autre : le dépôt courant n'est pas touché. Le paquet remplace ensuite l'application installée.

<Callout type="warn">
  `make beta BRANCH=main` ne revient en arrière que si la branche essayée n'a pas migré la base. Sinon, la version de
  `main` refuse de démarrer sur ces données.
</Callout>

## Télécharger le paquet depuis la CI

Le workflow « Apps » de GitHub Actions (`.github/workflows/apps.yml`) construit le `.deb` et l'APK Android, pour chaque push sur `main`, chaque étiquette `v*`, ou à la main.

<Callout type="info">
  Ce workflow est sur la branche `ci/build-desktop-and-android`. Il ne tourne qu'une fois cette branche fusionnée dans
  `main`.
</Callout>

| Job                           | Ce qu'il produit                                                                     | Artefact                                     |
| ----------------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------- |
| « Desktop package (.deb) »    | `make desktop-package`                                                               | `bosco-desktop`, gardé 30 jours              |
| « Android application (APK) » | `make android`, puis `bosco-android-<commit>.apk`                                    | `bosco-android`, gardé 30 jours              |
| « Release »                   | sur une étiquette `v*` seulement : une release GitHub avec le `.deb` et l'APK joints | fichiers de la release, sans limite de durée |

**Depuis l'onglet Actions** : ouvre une exécution du workflow « Apps » sur `https://github.com/fpasquet/bosco/actions`, puis télécharge `bosco-desktop` dans la section _Artifacts_. GitHub le livre en `.zip` qui contient le `.deb`.

**Depuis une release** : sur `https://github.com/fpasquet/bosco/releases`, le `.deb` d'une étiquette `vX.Y.Z` est joint tel quel.

**En ligne de commande**, avec `gh` :

```bash
gh run list -R fpasquet/bosco --workflow apps.yml --branch main --limit 5
gh run download <run-id> -R fpasquet/bosco -n bosco-desktop
gh release download v0.2.0 -R fpasquet/bosco --pattern '*.deb'
```

Puis installe le paquet téléchargé avec apt. `make desktop-package-install` ne lit que `apps/desktop/out` :

```bash
sudo apt install ./bosco-desktop_*_amd64.deb
```

Si apt signale que `_apt` ne peut pas lire le fichier, copie-le d'abord dans `/tmp`.

## Au lancement

L'application cherche un service Bosco sur `http://127.0.0.1:4870` :

- **aucun service ne répond** : elle démarre le sien, celui du paquet ;
- **un service répond déjà**, par exemple le service systemd de [l'installation](/docs/installation#en-faire-un-service-de-lutilisateur) : la fenêtre « Bosco tourne déjà sur ce poste » propose « Se relier au service », « Remplacer le service par l'application » (qui désactive le service systemd) ou « Quitter ». Le choix est gardé.

Si le service ne démarre pas, la fenêtre « Le service Bosco n'a pas démarré » montre ses dernières lignes d'erreur.

## La fenêtre

La fenêtre affiche l'interface de Bosco, comme le navigateur. Les liens vers l'extérieur s'ouvrent dans le navigateur. **Fermer la fenêtre la masque** : Bosco reste dans la barre système et continue de notifier. Relancer l'application ramène la fenêtre existante, sans seconde instance.

## La barre système

L'icône change dès qu'une session t'attend, et son infobulle dit combien : « Bosco · 2 sessions t'attendent ». Un clic sur l'icône ouvre la fenêtre. Le menu se lit de haut en bas :

1. « Relancer Bosco · version … installée », seulement après une mise à jour.
2. L'état : « Bosco · rien ne t'attend », « Bosco · 1 session t'attend » ou « Bosco · N sessions t'attendent ».
3. Une ligne par session qui t'attend, la plus ancienne d'abord, qui ouvre la session :
   - une autorisation : « Ajouter les catégories au budget du foyer · Bash npm run db:migrate » ;
   - une question : « Récapitulatif quotidien des réservations · question de l'agent » ;
   - un tour terminé : « Migrer le logger vers OpenTelemetry · tour terminé ».
4. « Ouvrir Bosco », « Nouvelle session » et la case « Suspendre les notifications 1 h ».
5. La case « Lancer au démarrage » et « Quitter Bosco ».

« Lancer au démarrage » écrit `~/.config/autostart/bosco.desktop` : Bosco démarre avec ta session, fenêtre fermée, dans la barre système.

## Les notifications

Quand l'application tourne, c'est elle qui affiche les notifications, avec celles du système : le service ne les envoie pas en double. Le titre dit le type et le projet, « Autorisation · maison », le texte donne le titre de la session et un extrait. Un clic ouvre la session dans la fenêtre.

Une autorisation ou une question part en priorité critique : elle reste affichée jusqu'à ce que tu la fermes. Rien ne s'affiche quand la fenêtre est au premier plan (l'interface montre un message bref) ni pendant une suspension d'une heure. Ce qui notifie se règle dans [Réglages › Notifications](/docs/guides/notifications).

## Lancer l'application depuis le dépôt

Pour développer l'application elle-même, sans paquet :

```bash
make desktop           # construit, puis ouvre l'application du dépôt avec le Node du poste
make desktop-install   # ajoute au menu des applications une entrée qui lance l'application du dépôt
```

Depuis le dépôt, le bac à sable de Chromium demande un `chrome-sandbox` qui appartient à root. Sans lui, l'application se lance sans bac à sable et affiche la commande `sudo chown … && sudo chmod 4755 …` qui le configure. Le paquet `.deb` le configure à l'installation.
