# Classes sémantiques

Celles de daisyUI d'abord (`btn`, `card`, `badge`, `input`…), réglées par son thème, pointé sur les tokens
(`src/styles/theme.css`). Le projet ajoute les siennes pour ce que daisyUI n'a pas, à côté de leur composant ou dans
`src/styles/classes`, rassemblées par `src/styles/components.css`. Le réglage global d'une classe de daisyUI, ou une
classe posée avec elle, s'écrit dans la sous-couche de base de daisyUI (`@layer utilities { @layer daisyui.l1.l2.l3 { … } }`) :
ses modificateurs et les utilitaires du JSX l'emportent encore.
Les variantes sont des classes de modificateur (`btn-primary`, `badge-soft`) ;
les états passent par les attributs d'accessibilité et les pseudo-classes (`aria-selected`, `aria-invalid`, `:focus`,
`:disabled`). Seul `data-state`, posé par Radix, sert aux animations d'ouverture et de fermeture. Les composants de
`src/shared/ui` les posent ; le JSX peut aussi les utiliser directement, par exemple sur un lien : `<a className="btn btn-outline">`.

design system s'ajoute ici dans le même changement (`audit.mjs` signale celles qui manquent).
